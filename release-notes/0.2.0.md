A large release: posts and their images now publish in one commit, the access token moves out of your vault into Obsidian's secret storage, Obsidian-only syntax is converted for the web, and sixteen bugs are fixed.

## Before you upgrade

- **Requires Obsidian 1.11.4 or later**, for its secret storage.
- **Your access token moves automatically.** On first load, the token in the plugin's `data.json` is saved as a secret named `publish-to-github-token`, read back to confirm, and only then removed from `data.json`. A notice says when this has happened. If the move fails, the token stays where it was, keeps working, and the move is retried on the next load.
- **Using more than one device?** Secrets belong to the device, not the vault. The first device to load this version moves the token and clears it from `data.json`; once that syncs, set the token once in the plugin settings on each other device.
- **Images move into per-post folders.** The new *Group images by post* setting is on by default, so the next time you republish a post, its images are uploaded into a subfolder named after the post, and its links point there. The old copies in the flat folder are left in place. Turn the setting off to keep the flat layout.
- **Expect a one-line change on each existing post's next publish.** The published copy now has exactly one blank line after the frontmatter, where it used to have two.
- **Your filenames are unchanged.** The new *Default filename* setting is `{{title}}.md` on an upgraded install, which is the old behaviour, so existing posts are not republished under new names. New installs get `{{slug}}.md`.

## New

### One commit per publish
A post and its new or changed images are now committed together through GitHub's Git Data API. Everything lands at once or nothing does: a failed publish leaves the repository exactly as it was, instead of leaving uploaded images behind without their post.
- The commit message is your template, followed by a list of the files it touches, each marked new or changed.
- Before committing, every file is checked against the version you reviewed. If one has changed on GitHub since, nothing is committed.
- Pushes that only touch other files are no obstacle: the plugin re-checks against the new branch head and commits on top of it.
- Other refusals, such as branch protection, are reported in GitHub's own words.

### The preview knows what will actually change
Images are checked against the repository before the preview opens, and each is listed as *new*, *changed* or *unchanged, skipped*.
- A post identical to the file already in the repository is no longer committed or treated as an overwrite. Only its new or changed images are uploaded.
- When nothing at all would change, the preview says so and the button is disabled.

### Access token in secret storage
The token now lives in Obsidian's secret storage on the device. The plugin's `data.json`, and so any backup, sync service or git repository that copies your vault, holds only the secret's name. The settings use Obsidian's own secret picker. A device without the secret is told to set it, rather than failing with a bare 401.

### Obsidian syntax converted for the web
A new *Obsidian syntax* settings section, with these defaults:
- **Links to other notes** (`[[wikilinks]]`, note embeds like `![[Other note]]`, and markdown links to `.md` files) are published as plain text: the link's display text, or else the note's name. The review window lists every link it converts, in case one was meant to point at a page on your site.
- **Comments** (`%% … %%`) are removed, before images are collected, so an image inside a comment is not uploaded.
- **Highlights** (`==text==`) become `<mark>text</mark>`.

Code blocks and inline code are never touched.

### Placeholders and a default filename
One set of placeholders now works in default property values, the commit message, and a new *Default filename* setting:
- `{{title}}`, `{{filename}}`: the note's name.
- `{{slug}}`: the note's name, URL-safe (`my-post`).
- `{{date}}`, `{{time}}`, `{{datetime}}`: now.
- `{{date:MMMM D, YYYY}}`: now, in a format of your own, using the same format tokens as Obsidian's date settings.
- `{{path}}`: in the commit message only, the post's path in the repository.

The filename a note is published under is remembered, so republishing goes back to the same file even if the template or the date has changed. The review window marks it *as last published*, and the memory follows the note through renames.

### Video, audio and PDF embeds
These used to be written as markdown image syntax, which shows as a broken image on a site. Now:
- **Video** becomes `<video controls>`, keeping its Obsidian width under the same setting as images.
- **Audio** becomes `<audio controls>`.
- **A PDF** becomes a plain link.

The alt text field becomes a player's screen-reader label, or a PDF's link text.

### Links after publishing
The success notice now links to the commit and to the post on GitHub, and stays up for 15 seconds so there is time to click.

## Fixed

### Images
- **Images from different posts overwrote each other.** Two posts that each embedded a different `diagram.png` shared one file in the flat attachment folder, so publishing the second silently replaced the first post's image. Each post's images now get their own folder.
- **Names written entirely in a non-Latin script all became `attachment.png`,** and collided. Such names now get a short hash of the original name instead.
- **An image embedded twice was uploaded twice,** under two names. Embeds of the same file now share one upload, and renaming one renames them all.
- **Image names typed in the review window were used exactly as typed.** A space broke the link, `../` could escape the attachment folder, and two different images could be given the same name. Typed names are now cleaned like the automatic ones, keep the image's own extension, and must be unique.
- **Checking whether an image already existed downloaded the whole image,** and treated any failure as "nothing there", leading to a confusing 422 error. The plugin now reads a whole folder's hashes in one request, and a failed check stops the publish with the real error.

### Publishing
- **Retrying after a conflict always failed.** Going Back to the preview reused the file version that had just been rejected. A failed publish now makes the preview read the file afresh.
- **A file someone else created at the path after it was checked** produced GitHub's cryptic "sha wasn't supplied" error. It is now explained as the conflict it is.
- **The preview offered "Overwrite" for a post identical to the one on GitHub,** and publishing it made a commit that changed nothing.
- **A failed publish logged an unhandled error to the developer console,** and the overwrite confirmation stayed open over the preview's Back button.

### Content and frontmatter
- **A frontmatter value ending in `---`** (such as `title: Pros---`) ended the frontmatter early. The rest of the YAML fell into the body, where its closing `---` matched the default break marker and cut the post down to a stray line.
- **The break marker matched inside code blocks and on heading underlines,** so a YAML snippet in a code block, or a heading underlined with `---`, cut the post. The review window now also notes any marker it passed over as a heading underline.
- **Two blank lines appeared after the frontmatter** instead of one.
- **A post name like `Release 1.2` was published without `.md`,** because `.2` was taken for an extension. Only `.md`, `.mdx` and `.markdown` now count.
- **Characters like `$&` in a note's name garbled the commit message.**

### Settings
- **The repository folder suggestions stayed empty** if a folder field was focused before the token was entered. A failed lookup is now retried, and changing the connection settings refreshes the list.
- **On a fresh install, adding a property in settings also changed the built-in defaults** for the rest of the session.
- **Very short tokens shredded error messages:** redacting a token of a letter or two removed those letters from every message. Only realistic tokens are redacted now.

## For developers
- 73 unit tests (`npm test`, with vitest) cover parsing, naming, syntax conversion, placeholders, the diff, and the single-commit publish against an in-memory fake of GitHub's API.
- A new CI workflow type-checks, tests and builds every push and pull request. Releases are published only if the tests pass.
- Release notes are now taken from `release-notes/<version>.md` when that file exists.
